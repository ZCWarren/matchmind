# How to read MatchMind

MatchMind is a broadcast control room for football. It is not one feed and it is
not a chatbot. It separates four things that are usually mixed together.

## 1. The data itself

This is what happened in the match:

- event type: pass, pressure, carry, shot, goal, card, sprint, substitution
- clock, player, team, location, end location, outcome
- event IDs that let every later claim point back to a row

The event stream is synthetic, deterministic, and generated by MatchForge. It is
the only raw input to the rest of the system.

## 2. Deterministic analytics

These are calculations over the event stream, not AI guesses:

- xG and xT
- pressure and pass difficulty
- control and chaos
- momentum, rhythm, verticality, pass completion
- sprint and ball speed

Every metric carries a formula version and the event IDs used to compute it. If a
number appears in a claim, it should appear in this layer first.

## 3. The AI explanation

The agents produce language, not numbers:

- TacticalAnalyst writes the tactical argument and claims
- StoryProducer writes the broadcast cue
- AudienceEditor writes analyst / casual / player versions
- FactChecker audits the claims (advisory)
- Director decides approve / hold / kill

The rule is: the models explain the evidence, they do not calculate the football
numbers. The UI labels this layer **AI EXPLANATION**.

## 4. Evidence and the release gate

Every claim points to:

- event IDs
- metric references with values and formula versions

The deterministic verifier checks those references. If a claim is unsupported,
the cue is withheld. The LLM FactChecker is a second opinion, not the release gate.

The UI labels this **EVIDENCE** and the program monitor **VERIFIED CUE**.

## Reading the Studio

| Area | What it is |
|---|---|
| Top bar | fixture selector, score, clock, replay, safe areas, Generate |
| Left rail | match card, detected key moments, event feed |
| Center | pitch + current event; deterministic stat row below |
| Right top | program monitor with the exact cue that will air |
| Right middle | agent rundown: explanation, claims, approve/hold |
| Right bottom | evidence drawer for the selected claim |

The colored tags in Studio make the layers explicit:

- `DATA` cyan: event feed and tracking
- `DETECTED` grey: moments found by the deterministic detector
- `DETERMINISTIC` / stat row: calculated metrics
- `AI EXPLANATION` lime: language from the agents
- `EVIDENCE` coral: claim-level references
- `VERIFIED CUE` lime: the monitor output

## The hero example

At 72:12, Nova Harbor vs Orion North is 1-1.

- **Data**: NHR-08 completes a pass from x=38.0 to x=62.0 under 0.82 pressure.
- **Deterministic**: the pass has 8.7 difficulty, adds +0.1736 xT, and is tagged
  `line_break`; it is followed by an NHR-14 sprint and a saved shot.
- **AI explanation**: NHR-08 breaks ORN's press trap and sends NHR-14 through.
- **Evidence**: the claim carries `e-000974`, `event_pressure 0.82`,
  `xt_delta +0.1736`, and the event window.
- **Verifier**: pass. **Director**: approve. **Operator**: approve or hold.

A held insight is not a bug. It means the release gate found something that
should not go on air yet.

## Overlay

`/overlay` is a transparent 1920x1080 browser source for OBS or vMix.
`/overlay?bg=1` is the dark preview. Templates:

- lower third: headline, stat, subline
- stat card: xG, xT, event pressure
- momentum: control share, chaos, pressure
- speed alert: match top speed
- pressure map: recent pressure and pass locations

All templates read the same verified cue.

## Fan

`/fan` is the second screen. Switch fixture, analyst / casual / player, and
English / Spanish / Chinese. The Player tab also has a deterministic event log
for any player: passes, completion, shots, and top speed. The match recap is
composed deterministically from the event stream and labels.

## Cached vs live

- **Public static demo**: five cached insights, instant, no API key. Live
  generation and the WebSocket feed are disabled.
- **Local app**: the full five-agent graph, MCP analytics server, retries,
  WebSocket replay, and Generate button.
- **Generate** on a cached moment returns in milliseconds. A new live insight
  takes the length of a model run, which is why the demo precomputes one moment
  per fixture.

## Quick path

1. Open Studio and pick a fixture.
2. Read the cue in the program monitor.
3. Read the agent explanation and the evidence drawer.
4. Switch L3 / STAT / MOM / SPD / MAP.
5. Hold, then approve.
6. Open Fan and switch profile/language.
7. Open About for the system story.
